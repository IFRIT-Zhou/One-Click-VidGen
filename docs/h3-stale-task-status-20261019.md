# H3 旧任务误显示 running（2026-10-19）

## 现场证据

用户截图的任务为 `h3job_622d53ed370d4542b67f563dc7696da4`，属于 liuyujiang95。北京时间 2026-10-18 23:50:45.987 创建，23:59:59.105 开始，2026-10-19 00:04:44.459 以 `EXECUTION_OUTCOME_UNKNOWN` 失败。该任务没有结果文件。相关 Windows 重启原因仍在调查，本文不将状态显示修复视为重启原因修复。

Nginx 当前日志记录该任务最后一次 GET 状态查询为 2026-10-19 00:01:39，此后没有新的查询或结果下载记录。2026-10-19 下午检查时，这个账号最新 H3 任务仍为 09:55 创建、09:57 取消的另一任务。截图中的编号不是下午新提交的任务。

同账号三个上午成功结果使用 FFprobe 检查：6.583333 秒（2,034,580 字节）、15.083333 秒（6,181,117 字节）、9.416667 秒（3,919,523 字节），均有 H.264 视频流。因此现有证据不支持“截图任务在下午返回了零秒视频”；需要实际零秒文件或客户端诊断进一步定位其他预览/导出问题。

## 原因与修复

客户端中断恢复时，`recover_interrupted` 将 H3 镜头标记为 `unknown` 并保留原任务身份，但没有清除 `video_progress_message`。界面优先使用旧进度文本，因此旧值 `running` 覆盖“状态待核实”的提示。恢复本身不会访问云端；继续查询原任务也不会新建任务，故旧编号不会让空闲 GPU 再次工作。

- 恢复与查询/下载异常均明确提示尚未核对云端结果。
- 前端以 `unknown`、`failed`、`stopped` 状态为准，不被旧进度文本覆盖；兼容已有项目记录。
- 查询确认原任务失败后，显示结构化错误代码和说明，禁止下载失败任务的结果。
- 下载结果在 FFprobe 抛异常、时长非有限值/非正值、校验和不符时删除无效文件，保留原任务编号供继续下载，不标记成功，也不重新提交。

用户应先选择“继续查询原任务”，取得失败详情；确认要重做时使用单独的重新生成操作。不能通过自动清空旧编号来隐式重复生成。

## 验证

- Python H3 客户端测试 21 项通过，涵盖中断恢复、旧失败任务只查询不提交、不下载失败结果、零时长/NaN/FFprobe 异常清理。
- 前端 H3 测试 11 项通过，涵盖旧 `running` 文本不能覆盖待核实/失败/停止状态。

这是 GitHub 客户端修复，需要用户更新并重新启动本地客户端才能生效；不需要修改集群 Cloud API，也不会远程改写用户项目。
