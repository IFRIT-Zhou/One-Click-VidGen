# 动态视频导演规则：单张核心参考 v2

本轮保留图文视频实现，视频侧从成熟规则派生独立合同：

- Agent 0 继续复用 `story_agents.create_story_context` 的全文、身份与事实资料整理。视频上下文额外携带用户画风、人设、世界、素材说明和导演策略。
- Agent 1 提取谁对谁做什么、问题与回应、条件与结果，保留原文的事实/假设/引用边界及局部连续性。表达目的简短具体；按完整意思和字幕边界选择动静并分组，不用最后一句结论覆盖前面的事件。
- Agent 2 主导场景与构图，比较两个表达候选。动态核心图以前段有内容的场面为主，可自然作为首帧；允许有清楚主体、归属和层次的复合参考素材。场面不必先画出所有后续景物或最终结局；不固定主持人、气泡、会场或元素数量。
- Agent 3 在 Agent 2 已选定的场景和表达上编排动作、回应与变化，只为可执行性作局部适配，不再次自由选择全局场景或隐喻。产出 v2 `motion_plan`；程序由它生成可见 `action`。后续新状态与景物只要由原文支持即可设计，不要求预先出现在核心图中。
- Agent 4 合并人物属性、动作和构图为精炼图像提示词。动态核心图按 `reference_visual/reference_participants/reference_texts` 定稿；静态使用原核心设计。三个小标题保持既有 UI 兼容，`intent` 原文仍由程序一次性写入“本图旨在”。
- Agent 5 只定稿当前方案，以场景保持要求、逐阶段段落、结尾要求返回。程序验证阶段 1～N 完整且顺序不变，再组装正文，前置经用户确认的 `SINGLE_REFERENCE_GUIDE`。保存后的整份 `video_prompt` 就是用户看到并提交的文本；不在接口提交时另加隐藏指令。静态跳过 Agent 3、5。

`normalize_shots` 从权威字幕重建 `source_subtitles`，保留 `semantic`、`visual_design`、`motion_plan`，避免模型/客户端旧字幕成为后续依据。阶段只是一个镜头内的表达顺序，不新增字幕、时间轴切口或生成请求。

v2 把图的空间构成与视频的时间顺序分开：

- `participants/beats` 记录整镜主体和阶段，`reference_participants` 只列核心图中可见的主体。
- `reference_beat` 是核心场面接近的早期阶段基准，不限制参考图的素材集合。
- `reference_texts` 独立列图中实际可见短字，允许跨阶段素材或图例，也可为空；无需等于某个阶段，更不必取所有阶段并集。
- 视频各阶段 `texts` 使用完整状态：前一阶段的字未再次列出则应消失。气泡图案通过动作正文描述，不为图案强加文字。
- 结尾保持当前结果，除非原文要求回返，不重新堆出早期气泡或复刻整张核心参考图。

无人物、无文字、物体过程均有效。程序校验结构、主体/文字的显式交接、阶段完整性；这些检查不证明动作语义或生成画面的美学质量。主体称呼校验按计划约定名称，不声称能自动识别任意别名。

旧 v1 阶段方案和无方案草案继续按原格式读取、编辑，不自动迁移或重新调用 Agent。用户手改最终提示词不在确认时强制改回计划。阶段方案的字幕分组发生拆分、合并、删除转移时，仅使受影响镜头的计划与衍生提示词失效，避免对应错位。

普通流程仍使用同样的 Agent 数量和批次调用次数。两个创作导演收到角色相关的方法示例，定稿员只收到当前任务方案。明确交接错误最多修订一次，仍失败则报告。没有接入多宫格或裁剪。

上下文 `video_direction.director_revision=single_core_v2_20260917_speech_attribution` 和 Agent 2 的“单图 v2”日志可用于核对新规则是否生效。完整成功样本与评估边界见 `VIDEO_SINGLE_REFERENCE_CASE.md`。

## 发言与想法归属（2026-09-17）

本次实测发现两处偏差：Agent 1 把受众的典型回应概括成讲者自己列举标签；另有一镜 Agent 2 写对了观众提问，Agent 3 却将气泡移到讲者，动作正文和 `texts.owner` 也不一致。这是可改善的语义交接问题；没有进行不同模型的对照测试，不能据此判定 Flash 的能力上限。

- Agent 1 在 `semantic.speech_turns` 中记录短原文、发言/想法归属者、对象、类型和依据。区分旁白朗读者与被引用的人；保留跨镜省略的问答关系，作者自问自答不能凭问号捏造听众。
- Agent 2 对照原文核对、补齐归属，不能只服从旧摘要。若仅纠正错归属，可返回 `attribution_correction` 理由，并局部纠正目的/递进关系；普通规划也接收核对后的归属记录，不再只有调整字幕后才接收。
- Agent 3 保留双方关系，图案气泡与文字气泡都要明确归属；群体可由其中几人分别回应。Agent 4/5 不因主角是旁白音色而重新分配发言。动作、气泡指向、`texts.owner` 须在同次生成中自检一致。
- 归属记录随任务保存与续跑；拆分/合并/移边界时清除受影响镜头的旧记录。单镜手动修订后以用户的新阶段方案为准，清除旧自动归属，避免定稿时反向覆盖用户修改。

不新增 Agent 或常规 API 调用，不增加语义硬门禁。可选记录异常或原文锚点不属于当前字幕时忽略该条，以原字幕继续设计；旧任务缺少字段仍可读取，不会因为打开页面自动重规划。只修改动态视频链路，图文视频不变。离线回归验证数据交接与行为边界，生成质量仍需用户实测。
