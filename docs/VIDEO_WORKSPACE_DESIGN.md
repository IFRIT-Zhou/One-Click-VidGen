# 动态视频板块：第一轮实现与后续接入

界面入口称板块，Python 流程称模块，模型角色称 Agent。

## 已实现的第一轮

- 动态视频新建页共用图文视频的文案/上传音频、TTS、画风参考图、编排、BGM 和字幕样式 UI。`dynamic_video` 任务强制分步模式，只先走现有音频和校对；确认精修快照后复制到动态草案。后端拒绝这种任务推进旧图文出图流程。
- 新任务自身的创建参数保存为 `creation_parameters`，其画风、人物、参考素材和编排供动态规划使用；BGM/字幕参数保存待后续视频渲染接入。与“仅导入旧作品音频”是不同路径，不继承旧作品画面设定。
- 正式模块 `module6_dynamic_video.py` 负责图片上传、付费提交前落盘、任务ID持久化、状态查询、下载及参数指纹校验。动态镜头页已接通单镜试生成与全部未完成镜头生成；只在用户确认操作后发出请求，导航和打开任务不提交。
- 视频 Agent 已拆为：Agent 0 全文理解、Agent 1 镜头分组与动静选择、Agent 2 核心画面草案与按需素材、Agent 3 动态阶段与代表状态、Agent 4 核心分镜图定稿、Agent 5 视频提示词定稿。两份定稿共享阶段方案；程序在用户确认前检查字幕覆盖、时长、参考图号和提示词合同。详见 `VIDEO_DIRECTOR_ADAPTATION.md`。

- 独立动态视频预览入口，新建独立任务，可从已有成功项目仅导入配音、最终 SRT 和其中的时间戳。不导入旧图片、参考图、画风、人物/场景设定、画面映射或横竖屏设置；新画面设定由用户独立填写。原项目保持不变。保留折叠的 SRT 测试入口；字幕是只读时间基准。此前已创建的旧版导入草案不自动清理，界面提示重新创建。
- 复用 Agent 0 全文理解；视频 Agent 1 按连续字幕分组、选择静态或动态；动态 Agent 设计过程；分镜定稿 Agent 写图像与视频提示词。当前分镜定稿是独立初版，并未直接调用原图像 Agent 2 和图像定稿员，后续需对照已有质量规则接入。
- 持久化状态 draft → planning → storyboard_review；规划中断恢复为可重试草案。规划失败保留旧镜头。
- 编辑表达目的、动态过程、动静类型、两类提示词；拆分、合并、新增空白镜头、删除；所有结构操作完整保留字幕覆盖。
- 使用时长由首字幕开始至末字幕结束计算（包含间隔），请求时长向上取整且至少4秒。超15秒的动态分组由按需 Agent 1B 在字幕边界语义拆镜；只有单条字幕自身超限才独立静态，单句不私自切开。
- 乐观版本校验防止旧页面覆盖；独立工作目录 workspace/video_studio/<user>/<id>。

## 尚未接通，不应宣称已完成

1. 文案/TTS、上传音频/识别已复用现有分步音频流程，动态任务音频确认到分镜已接通；尚需真实任务回归。普通图文分步项目导入暂未开放。
2. 新任务参考素材上传与说明编辑尚未接入；不可从来源项目自动继承。规划契约支持按需选择素材。视频图1为核心分镜图，其余按本镜选中顺序编号图2起。
3. 核心分镜图生成、上传替换、重绘与场景协调已接通；已支持以核心图为图1、仅本镜选中素材为图2起生成视频。暂不传参考视频/参考音频。
4. 视频 API 配置、用户确认提交、查询、下载及逐镜浏览器预览已接通；需要用户在 OCV 中实测。开发回归使用模拟服务，不消耗真实视频额度。
5. 本地视频替换、选取片段起点、整片混合渲染、字幕/BGM、FFmpeg 与 HP 两路径验证尚未接通；当前看到的是各镜原始生成片段，并非最终成片。

## 首个接口合同

POST /openapi/v2/rhart-video/sparkvideo-2.0-fast/multimodal-video

prompt、resolution、duration 为字符串；imageUrls 最多9张；首版 generateAudio=false，不传视频/音频参考。
ratio 显式16:9或9:16，分镜图同项目比例。480p/720p报价未确认，测试前核价。
realPersonMode=false 用于简笔画测试；returnLastFrame=false。后续首尾帧续接另做。
POST /openapi/v2/query，body={taskId}。成功结果地址格式需真实短片测试验证。

不自动重新提交状态不明的付费任务。关键动作应在实际使用时长内完成，额外尾部保持可裁切；此为规划约束，模型是否遵循仍需用户预览。

## 动态镜头生成与安全续跑

- 核心图确认后进入独立的“动态镜头”阶段。推荐先试当前一镜，再处理全部未完成镜头；静态镜头保留图片，不付费生成视频。批量生成按“接口与服务”保存的多 Key 与单 Key 并发限制执行；任一镜出错后停止尚未启动的镜头，已经并行提交的云端任务继续保存身份并查询。
- 接口配置统一放在“接口与服务”，通过 `/api/video-model` 保存独立的地址、提交/查询/上传路径、多个 Key、480p/720p 和并发限制。可由用户明确复用同站点兼容的全部图像账号；动态镜头页只显示摘要，不再填写密钥。仅支持当前异步多模态协议，不因可填写地址而宣称兼容任意服务商。号池未接入。
- 若检测到兼容的现有图像接口，只提示用户可选择复用；需用户明确点击才复制到独立视频配置。不自动复用任意站点的密钥，不在响应、任务配置快照或浏览器缓存返回密钥。
- `/api/video-studio/{id}/videos/generate` 接收任务版本、可选镜头ID和显式失败重试标记。每次尝试独立保存 `assets/videos/<shot>/attempt_NNN/request.json`、实际参考图副本、`task.json` 和 `clip.mp4`。提示词按用户确认后的最终文本提交，不追加隐藏 Agent 指令；接口固定静音、不传配音。
- 未知状态有任务ID时，仅查询/下载原任务；没有任务ID时冻结，并提示先向服务商核实。只有云端明确终态失败才允许用户选择“重新付费生成”，旧任务身份保留，不删除旧状态。已完成镜头不会重复提交。
- 项目另存执行开始标记；执行后若 `task.json` 丢失或编号不一致，保留原编号并阻止提交，不能把文件丢失当成“没生成过”。尚未执行的请求快照、明确在付费提交前停止的任务可继续首次生成。已完成片段在本地丢失时，可使用完整的原任务状态重新查询和下载。
- 停止只停止后续提交和本地轮询/下载，不能承诺云端撤单或退费。重新打开任务只恢复本地状态，继续由用户点击。接口/模型或账户变化时不能无声查询错误来源的任务。
- `video_generation_ready → video_generating → video_review`；停止期间为 `video_stopping`。`video_review` 表示检查各镜素材，不是整片完成。已确认的分镜、字幕和核心图仍只读。
- 预览使用浏览器原生视频播放器，不依赖本地 FFmpeg；只做基础 MP4 容器/下载完整性检查，不声称验证了画面内容、动作质量或每一帧可解码。预览展示原始生成时长，稍后的混排合成才按字幕使用时长裁切。

## 超长镜头与规划续跑

- Agent 1B 复用用户现有语言模型设置，只接收需要修复的父镜头、相邻语境和程序计算的合法字幕跨度。正确镜头不重写；子镜保留完整字幕覆盖并分别确定表达目的。
- 局部模型修订最多两次。失败后程序按合法边界保守分区，避免可避免的短碎镜，保留动态类型并标注建议检查；原音频与字幕不变。单条自身超过 15 秒独立静态。
- `planning_state` 提前保存 Agent 0 理解、Agent 1 原分组及每次局部修订；后续按镜头记录核心设计、动态方案和两类定稿的完成状态。草案回调不等于阶段完成。
- 重试通过输入指纹检查后复用已完成步骤。字幕、参数或导演版本变化后重新规划，用户手动保存、结构编辑或确认方案会清除旧续跑状态，防止覆盖手改。
- 页面使用同一个规划按钮显示“继续未完成规划”；最终结果展示语义拆镜/保守拆分/超长单字幕静态的说明，不增加必选设置。

## 动态分镜的场景参考

- 已选择动态表达模式的任务沿用创建页画面编排中的 `scene_references_enabled` 开关，独立于图文视频的 `director_strategy`；“文字辅助”和“画面优先”均可使用。未带新模式字段的历史草案保留原先增强模式门槛，不会因重新打开任务激活原本关闭的场景参考。开关关闭时不调用场景协调员。
- `video_scene_references.py` 适配原场景协调员，按核心图实际承载空间分组。会场中气泡表达旅游或想象，不因解释/隐喻标签排除会场；实际切到其他地点的镜头独立处理。没有共用空间时保存空计划。
- 用户确认核心图生成后，先缓存场景计划并生成无人场景资产，再并行生成核心图。人物素材取动态分镜的 `reference_ids`，按请求局部图号排列，场景附在末尾；超出图像接口四张输入上限明确报错，不截断。
- 场景资产保存在该动态项目的 `assets/scene_references`，文件身份包含设计内容与配置指纹；不占用字幕或视频时间轴。续跑复用成功资产，场景失败时暂停核心图提交并保留可重试状态。
- UI 展示场景资产、所用镜头与实际使用版本。场景图片可重绘、替换、撤回；只更新资产，相关核心图由用户按需重绘，重绘默认带最新场景且可取消。
- 已经出完图的旧 `image_review` 任务可手动“补充场景参考”，不重新规划整片、不自动重绘已有图片。打开或刷新任务不会触发收费操作。
- 验证使用模拟 LLM/图像接口，涵盖按需绑定、缓存、并行、失败续跑、资产替换/撤回与重绘版本跟踪；实际视觉一致性仍需用户测试。

## 动态画面表达模式

- 动态视频新建页用“文字辅助 / 画面优先”替换图文视频的“稳健还原 / 叙事增强”选项；图文视频行为保持不变。这是画面表达策略，不控制最终成片的字幕。
- `dynamic_text_mode=text_assisted` 保留已有 Agent 的文字表达方式；`visual_first` 是少字而非禁字：优先通过动作、表情、人物关系和具体景物表达，必要的简短反应词、关键评价可主动保留，不需要用户逐字授权。不要将整段旁白复制或拆成许多文字气泡，不按固定字数或关键词模板裁切。菜单、招牌、物体标签等场景文字可以保留，想象气泡优先画图案。
- 新建动态任务默认 `visual_first`；缺少字段的旧任务、草案和预设按 `text_assisted` 读取，不自动重新规划或修改已生成图片。显式选择随任务、参数回顾、配置复制和草稿保存。
- 模式经创建参数传入导演上下文，作用于核心画面设计、动态阶段、两份最终提示词及单镜重新设计；不改动配音、字幕或分镜时间边界。更换模式属于规划输入变化，不能复用另一模式的规划缓存。
- 保留原文和发言归属作为内部语义依据，不以字符串删字代替画面设计。最终图片反推仍客观记录实际可见内容，不为符合模式而虚构识别结果。开发测试采用模拟 Agent，不承诺模型绝对不出字，实际视觉效果需生成后检查。

## 定稿格式与核对提醒

- 图像定稿 Agent 输出 `image_sections` 三个内容字段：`characters_and_style`、`scene`、`constraints`。程序统一按人物与画风、画面内容、必要限制排版，表达目的仍使用已确认的 `intent`；没有额外限制时最后一段可省略，不补造禁字或无人规则。仍兼容旧接口返回的 `image_prompt` 自由文本，不改写已保存或手动编辑的内容。
- 工作规则的标题不再作为输出分节交给模型模仿。结构字段缺失等在定稿时进行一次有界修订，不等到整轮结束才发现。纯标题和顺序问题不属于图像接口的执行条件，不触发黄色提示。
- 程序仍保留字面核对记录，但主体名称、归属名或气泡/对话框等容器措辞差异只作单镜折叠备注，不自动调用定稿 Agent 重试。它们不代表语义一定出错。
- 选定画中文字未找到、已选文字与全面禁字指令矛盾、核心图出现未选阶段文字，才计入黄色提醒；仍允许人工检查后继续。此类问题只进行一次定稿修订，不能无限重试。
- 空提示词、无效参考素材、时长越界、阶段缺失等真正无法执行或破坏时间轴的问题继续阻止推进。旧任务的格式提醒由显示层直接过滤，无需重新规划或额外 API 消耗。
