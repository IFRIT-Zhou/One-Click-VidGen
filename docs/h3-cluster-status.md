# H3 集群部署与验收（2026-10-12）

已部署并启用。当前客户端选择“集群 H3（测试免费）”，通过已登录账号调用 .1 Cloud API；.1 统一调度 .3 两个独立 GPU 容器。H3 不扣积分。

## 操作流程

按现有动态视频流程先配音、确认分镜和核心图，再在动态镜头阶段选择“集群 H3（测试免费）”生成片段，最后合成导出。参考音频/对口型暂未开放，原配音在导出时合成；同一批次目前需统一 H3 渠道。界面展示允许的尺寸和时长，超限需拆分。

客户端只连接 Cloud API，不连接 .3 ComfyUI。接口前缀 `/api/v1/cloud/video`，包含 capabilities、assets、quotes、jobs、jobs/by-client-id、cancel 和认证 result 下载。任务编号由客户端内部生成并持久保存；网络中断继续查询原任务，避免重复提交。仅接受免费测试报价。

动态镜头页面的生成按钮上方提供“批量视频生成设置”，可选择集群 H3 等渠道及尺寸，确认后应用到全部动态镜头。应用只保存下次生成配置，保留现有素材；单镜头仍可独立调整。有未应用的批量修改时，需先应用或取消修改再批量生成。任务正在执行或结果尚未确认时禁止批量修改。

管理后台分别显示 TTS 与 H3 状态。空闲且调度器、队列和节点探针健康时显示“按需休眠”，不要求两个模型同时驻留。TTS 就绪需模型及音频处理服务正常；H3 就绪需容器、CUDA 引擎与队列探针正常，模型权重在任务执行时加载。探针过期或两容器同时运行会标记异常。

## 按需启停

.1 `ocv-gpu-scheduler.service` 已 enabled/active，空闲停止两容器。TTS：`ray-worker-managed`；H3：`ocv-h3-comfyui`。互斥切换前确认旧阶段无活动任务，恢复 TTS 必须确认模型就绪和派发恢复。调度器优先恢复未决执行，通常在阶段边界优先 TTS；TTS 有连续积压时采用120秒接单窗口后等待已接任务完成。不会为了新任务中断正在生成的正式 H3 片段。

部署期间按用户要求每30秒检查 .1 Ray 队列、活动任务及未转发 CloudJob；发现 TTS 时已中止可丢弃的 H3 测试并恢复配音，完成后继续部署。常驻调度器负责后续正式任务；上述30秒监测是部署期运维监测。

## 部署位置与模型缓存

.1 `/opt/cloud-api`；服务配置 `/etc/cloud-api-h3.env` 包含 `CLOUD_VIDEO_ENABLED=1` 和 `GPU_SCHEDULER_ENABLED=1`。API与scheduler共享私有存储 `/var/lib/cloud-api/h3`，结果需用户身份认证。

.3 `/opt/ocv-h3`，H3镜像 `ocv-h3-runtime:torch2.11-cu130-sage2.2`，ComfyUI0.38.2，torch2.11/cu130，官方SageAttention2.2编译支持RTX4090。仅快速版四个模型复制到 `/opt/ocv-h3/models-cache`，41.35GiB，容器只读挂载 `/models`。Windows原模型 `G:\trae_voice_over_video\models\comfyui` 保留。原TTS镜像及其依赖未修改。

跨WSL的9p顺序读取较慢，采用Windows原生FileStream→WSL stdin→ext4复制，四文件复制及校验合计254.91秒；源流、接收流、目标复读SHA256一致。manifest在models-cache/manifest.json。构建与回滚资料位于 `/opt/ocv-h3/build`，旧停止容器保留。不要同时运行旧手动phase脚本与常驻调度器。

API部署备份在 `/opt/ops-backups/h3-api-20261012-161501`、`h3-admission-20261012-162411`、`h3-enable-20261012-172523`。源码部署说明见 `deploy/cloud-api/H3_TEST_DEPLOYMENT.md`，节点配置见 `deploy/h3-node`。密钥和生命周期凭据只留在服务器，不入库。
