# H3 生成修复（2026-10-16）

本次修复覆盖桌面端前后端及集群 Cloud API；无需更换模型或重启 WSL、Ray、WireGuard。

## 原因与行为

- 集群默认尺寸原先由前后端分别取能力列表的最小面积，出现 384×640。Cloud API 现在明确返回横版 2048×1152、竖版 1152×2048 默认；客户端遵循服务端声明，旧服务无声明时取其支持的最大对应画幅。显式保存的旧尺寸保留，不静默降级。新任务参考图默认 2K，重绘覆盖字段仍为可选，不更改既有任务的明确画质。
- 分镜规划原先按 15/30 秒，H3 服务端仅允许 2–10 秒。集群规划现在最多 10 秒；沿字幕边界拆分并完整保留原配音和字幕。单条字幕自身超过上限时保留静态完整画面并给出原因。审核及新提交按实际单镜通道和向上取整的请求秒数检查，超限先阻止，不上传素材、不提交视频。
- RunningHub 新上传接口返回 `data.filename`，旧接口示例返回 `data.fileName`。现在兼容两者，仍要求工作流文件名；不会将下载 URL 当作文件名。HTTP200 的业务错误显示脱敏代码及消息。上传失败保持在付费任务提交之前，提交结果未知仍只查询原身份，禁止自动重复付费提交。
- 修复分镜保存、确认、拆分丢失单镜 `video_generation_options`，以及分步工作流忽略视频通道/H3 参数、旧项目遗漏时长设置的问题。重新生成使用已保存的本镜通道和尺寸。
- 成片原先固定 1080P，导致 2K H3 片段再次降采样。完成的 2K H3 片段现在使用 2K 合成画布；字幕同步缩放。旧低分辨率及其他通道保持原有导出行为。

## 验证

- `.3` 经真实 Cloud API 队列生成横版 2048×1152，2 秒请求输出 2.333 秒、24fps，推理约 94.6 秒。
- `.3` 经同一队列生成竖版 1152×2048，10 秒请求输出 10.125 秒、24fps，推理约 471.4 秒。额外时长来自工作流帧数对齐，导出按配音时间轴裁切。
- 两次均成功；ffprobe 核对了实际视频尺寸、帧率和时长。未使用成片插值放大替代原生生成。
- 前端 Vite 构建通过；规划、时长、路由保存/审核、上传协议和恢复身份的回归测试通过。FFmpeg 实际导出横竖 2K 纯净版和字幕版，保留 2K 画布。
- RH 上传兼容按官方响应样例模拟验证；未调用个人付费 RH 视频接口。
- 扩展检查发现既有 `test_cluster_revoice_step_compat.py` 的一项测试未创建 `other/画面时间线.json`，导致 TTS 指纹读取失败；该测试及 `tts_editor.py` 本次均未修改。

## 集群部署

2026-10-16 已更新 `.1` 的 `/opt/cloud-api/app/cloud_video_api.py`，原文件备份于 `/opt/cloud-api/backups/h3-2k-20261016/cloud_video_api.py`。服务已恢复 active；通过桌面云端客户端确认 capabilities 返回两种 2K 尺寸及默认声明。只重启 Cloud API，没有重启容器、Ray、WG 或 WSL。

已创建的项目若明确保存了 720P 或更低尺寸，需在本镜/批量生成设置选择新尺寸。升级不会修改未完成任务的冻结尺寸或幂等键，也不会自动重新生成旧视频。
