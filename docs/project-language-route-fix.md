# 项目规划渠道与 401 诊断（2026-10-13）

用户截图在 Agent 0 分镜规划报 `Google Gemini 调用失败 ... HTTP 401 APIKEY_USER_NOT_FOUND`。客户诊断显示原任务及分镜项目 `use_cloud_image_pool=false`，规划日志记录个人 API 配置，地址为 `https://llm.runninghub.ai/v1`。这是文本接口密钥认证失败，并非经 RunningHub 调用 H3。具体密钥无效、失效还是与地址不匹配，需由接口账号方确认。

云端账号对应时窗中，配音和六张图片成功；没有语言模型号池及集群 H3 请求记录。两份截图的项目编号不同，因此不能声称同一次任务已被远端复测。

现有行为按项目保存的号池开关决定语言路由，选择 H3 或修改首页开关不会改已有项目。这并非失败后回退。修复保留明确的个人 API 选择，新增项目级 `language_route`：`project` 保留原号池规则，`cloud` 使用号池，`personal` 使用个人接口。该设置适用于分镜规划、重规划和 H3 提示词转换，与图片和视频渠道独立。

本地 `POST /api/video-studio/{id}/language-route` 校验登录、版本及运行状态后保存；保留素材与规划检查点，暂停自动继续，不产生模型任务。服务端 Cloud API 无需变更。个人接口的 `APIKEY_USER_NOT_FOUND` 明确提示检查地址和密钥，或在当前项目切换云端，不把它混称余额或限流问题。

复现：实际执行规划 worker 和语言客户端代码，HTTP transport 使用模拟响应。个人配置返回同样 401；同一个项目明确切换 cloud 后请求 `/model-pool/v1/chat/completions` 并完成模拟规划。不是客户机器上的真实重跑，也未使用客户 Key。17 项路由/项目接口、13 项 H3、22 项 Gemini、2 项前端交互测试通过；Vue 生产构建通过。

恢复：更新并重启客户端，打开原项目，在“本项目规划渠道”选择“云端语言模型号池”，登录后保存，再点击“重试规划”。保留已完成配音及素材。只改首页开关不足以改变旧项目。

GitHub 更新通道 2026.10.13.1 指向当前 main 包；国内镜像未在本次发布中同步，不能使用旧版本固定镜像包冒充新版本。
