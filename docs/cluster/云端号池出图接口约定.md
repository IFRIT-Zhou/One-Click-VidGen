# 云端文本与图像号池接口约定

桌面端启用“使用号池”后，不再读取或提交用户本机的语言、图像或通用 API Key。Agent 0/1/2 和模块 4 使用当前云端登录会话的短期 Access Token 调用以下接口；积分预扣、结算、失败退款和真实上游账号轮换全部由 cloud-api 负责。

基础地址沿用 `CLOUD_API_BASE_URL`（例如 `https://example.com/api/v1`），所有接口使用 `Authorization: Bearer <access_token>`。

## 生产上游配置（2026-08-16）

`.93` 的文本号池已接入 RunningHub OpenAI 兼容接口 `https://llm.runninghub.ai/v1/chat/completions`，固定模型为 `google/gemini-3.1-flash-lite-preview`。图像号池已接入 GPT Image 2 低价版：

- 文生图：`POST https://www.runninghub.ai/openapi/v2/rhart-image-g-2/text-to-image`
- 参考图编辑：`POST https://www.runninghub.ai/openapi/v2/rhart-image-g-2/image-to-image`
- 任务查询：`POST https://www.runninghub.ai/openapi/v2/query`

2026-08-16 已用生产号池完成最小真实验证：Gemini 返回 7 tokens，文生图约 31 秒达到 `SUCCESS`，结果图片通过下载域名白名单。RunningHub 官方明确低价图像通道不保证稳定，且请求 2K/4K 时仍可能返回 1K；业务不应把它当作精确分辨率 SLA。

## 文本模型状态

`POST /model-pool/status`

用于启动前确认文本号池可用。成功响应示例：

```json
{"code": 0, "data": {"available": true, "model": "auto"}}
```

## 文本 Agent 推理

`POST /model-pool/v1/chat/completions`

该接口遵循 OpenAI Chat Completions 请求与响应结构。桌面端发送 `model: "auto"`，由服务端选择真实供应商、模型和账号；服务端不得向客户端返回上游 API Key。响应必须保留 `choices[0].message.content`、`choices[0].finish_reason` 和 `usage`。

Agent 0、Agent 1 与 Agent 2 都经过这个入口。当前 `google/gemini-3.1-flash-lite-preview`
按 RunningHub 2026-08-16 的折扣价计费：输入 `$0.000125/1K tokens`，输出
`$0.000750/1K tokens`。服务端按 `1 USD = 6.75` 积分换算并上浮 5%，保留 6 位
小数；预扣按请求的输入估算和最大输出计算，成功后严格按上游返回的实际输入、输出
tokens 结算并释放差额。上游失败不得消费。

## 生成图片

`POST /image-pool/generate`

桌面端应将本轮全部图片立即提交到云端队列，不设置客户端并发上限。cloud-api 不限制
单用户排队数量，也不设置人为的单账号并发阈值；Worker 每轮持续领取全部待提交任务，
优先选择当前运行任务最少的健康账号。真实上游容量不足、返回 421 或临时忙碌时，任务
保留在队列中等待或轮换账号，不得退化为“上一张完成后才创建下一张”。

请求兼容现有模块 4：

```json
{
  "prompt": "中文生图提示词",
  "aspectRatio": "2:1",
  "resolution": "1k",
  "imageUrls": ["https://.../reference.png"]
}
```

成功响应应包含任务 ID：

```json
{"code": 0, "data": {"taskId": "image_job_id"}, "reserved_credits": 5}
```

服务端必须在同一个事务中完成账户校验、积分预扣、号池任务创建和幂等保护，不能把真实号池 API Key 返回客户端。
集群按 RunningHub 返回的实际上游成本换算成人民币积分后上浮 5%，保留 6 位小数。
当前低价文生图与参考图编辑实测上游成本均为 `$0.015`，按 `1 USD = 6.75`
换算后实际结算 `0.106313` 积分。创建任务按 `$0.030` 上限预扣 `0.212625`
积分，成功后释放差额；失败时释放全部预扣。

新版 RunningHub 响应优先使用 `usage.consumeCoins`。该字段为空时使用美元字段
`usage.thirdPartyConsumeMoney` 并按配置汇率换算；两个已验证接口当前均返回
`thirdPartyConsumeMoney: "0.015"`。两个字段都缺失时才按
`IMAGE_POOL_DEFAULT_UPSTREAM_COST_USD=0.015` 兜底。`usage.consumeMoney` 币种含义不同，
不得混用。

## 查询图片

`POST /image-pool/query`

请求：`{"taskId":"image_job_id"}`。

运行中返回 `QUEUED` 或 `RUNNING`；成功时返回 `SUCCESS` 和可下载图片地址，例如：

```json
{"code": 0, "data": {"taskId":"image_job_id", "status":"SUCCESS", "imageUrl":"https://.../result"}}
```

失败时应返回稳定错误码和可读消息。服务端负责释放未实际消耗的预扣积分。

## 参考图上传

`POST /image-pool/media/upload`，使用 multipart 字段 `file`。成功响应：

```json
{"code": 0, "data": {"download_url":"https://.../reference"}}
```

## 号池状态

`POST /image-pool/account-status`

响应保持与当前模块队列探测兼容：

```json
{"code": 0, "data": {"currentTaskCounts": 0}}
```

本地模拟云端已经实现以上契约，可验证登录、逐图扣积分、提交、查询和下载；返回的是测试占位图，不代表真实图像模型质量。
