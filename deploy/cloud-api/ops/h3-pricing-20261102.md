# H3 阶梯计费

## .1 统一动态配置

将 `deploy/cloud-api/h3-pricing.example.json` 复制到 .1 的 `/opt/cloud-api/h3-pricing.json`，或用服务端环境变量 `H3_PRICING_FILE` 指定绝对路径。内容为：

```json
{"first_10_seconds_rate": "0.07", "additional_seconds_rate": "0.09"}
```

修改配置文件后，下一次能力查询或新报价立即使用新费率，不需要重启。建议写临时文件后原子替换，避免读取到写了一半的 JSON。费率须为正数，最大 100 元/秒，最多六位小数；分档边界固定为 10 秒。

`GET /api/v1/cloud/video/capabilities` 的 `pricing` 返回当前费率、10 秒分档、计费依据、取整规则和基于内容生成的版本号。客户端通过现有 Cloud API 登录连接获取，无需直接连接 .1 私网 IP。官网和客户端不内置费率、不校验固定价格版本；客户端只校验报价金额是否符合服务器随报价返回的费率。

未指定路径且默认文件不存在时，只有服务端使用下述初始费率；显式配置路径但文件缺失，或 JSON/费率无效时，新报价与能力查询返回 503，不静默回退。旧任务结算仅依赖已冻结报价，不受配置文件损坏影响。本改动需部署到 .1 后才会改变线上行为。

## 初始费率及结算

每镜按提交的请求时长计费，不按补帧后的输出时长。前 10 秒每秒 0.07 元，超过 10 秒的部分每秒 0.09 元；单镜总价向上取整到分，已是整分不额外加价。1 元对应 1 积分。

例：2 秒 0.14，10 秒 0.70，12 秒 0.88，14 秒 1.06。最长请求 14 秒及现有分辨率限制不变。

报价在已有 JSON spec 的 `_billing` 字段中冻结，无新增 H3 数据列。旧报价、旧任务没有该字段，仍按免费处理。客户端自动续报价时若金额变化会停止，要求重新确认。未提交报价不会冻结积分。

创建任务时预留积分；Worker 确认成功后扣费；失败和取消终态释放。无法确认远端状态时继续保留预留金额，避免恢复运行后重复扣费或先退款后免费执行。同一任务预留与结算均使用幂等流水键。官网完整动态视频流程的直接创建和取消入口也使用同一计费函数。

若同时部署已提交的奖励钱包 hooks，须先创建 `bonus_credit_grants` 和 `bonus_credit_reservations` 两张表（或执行完整邀请迁移 `20261028_referral_program.py`）；本次仅创建这两张表，不开启邀请注册入口。API、H3 Worker、官网及客户端应一起更新；旧客户端会主动拒绝非零报价。先完成当前在途任务或暂停新派发，再更新并重启全部 H3 Worker，避免旧 Worker 遗漏收费任务结算。

官网完整动态视频模块尚未纳入当前 Git 基线，其现网定价改动保存在 `h3-dynamic-site-pricing.patch`，包括直接创建任务的预留/取消释放以及两个页面的动态费率提示。对已有模块先用 `git apply --check` 检查，再应用补丁；不要将补丁应用于没有这些模块的全新检出。现有部署的进度、恢复及分辨率代码不应被本次 Git 中的文件整份覆盖，应只合入计费改动。
