`bb365387e166e608061b7dffbb1753f677cc8412133973b3194c65ccec5e6f27`

对应官方原文件 SHA-256：

`99bb765eaa8c4fcc5d279d7aa63f54cc92eeffdc9ecb4a9629996dfb214aceb8`

因此不能将其描述为“只改显存策略”，也不能保证所有显存溢出都会消失。

制作工具检查官方提交、原文件和替换文件哈希，不匹配即中止。
OCV 启动该组件时检查替换文件哈希；被其他更新覆盖时拒绝运行并提示修复。
后续升级 ComfyUI 必须重新审查这份替换，不能跨版本盲目复制。

## 制作与验证

1. 在新的 `runtime/comfyui/releases/<候选版本>/ComfyUI` 克隆上述官方标签。
2. 使用 `tools/stage_h3_v0382.py` 指定候选目录、原独立组件、外部工作流来源和预设文件。
3. 只在候选目录内更新 v0.38.2 的依赖，保存更新后的依赖清单；不要升级 OCV / TTS 环境。
4. 运行 `tools/validate_comfyui_component.py --candidate <候选目录>`，检查两套工作流全部节点。
5. 空闲显卡上分别指定 `--profile-id` 与 `--reference` 做短视频测试，再做日常分辨率回归。
6. 两套生成、回滚与许可证检查通过后，才决定默认激活和分发。

验证工具使用单独缓存、数据库与输出目录，不修改 `active.json`。
当前版本目录和用户外部 ComfyUI 不应被此流程覆盖。
